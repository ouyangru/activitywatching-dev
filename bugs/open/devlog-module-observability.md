# Devlog 模块筛选与异常可见性

状态：待生产验证

现象：`/devlog` 只有日志类型筛选，招聘进度、日历、邮件扫描等新模块混在通用 API 日志中；4xx/5xx、未处理异常和慢请求不够醒目，部分后台任务只写 journalctl，导致网页加载失败时难以定位具体模块。

代码改动：
- debuglog 条目增加 `module` / `level`，HTTP 请求按 path 自动归类。
- `/devlog` 增加模块筛选、仅异常/警告、仅慢请求，并高亮异常条目。
- 招聘后台邮件扫描和招聘↔日历 bridge 增加结构化事件日志。
- recruitment 入口补未处理异常日志，避免异常只进入 journalctl。

待验证：部署后复现一次正常首页加载、一次招聘进度批准写入，并确认 `/devlog` 能按模块筛选；再人为触发一个可控 4xx/失败请求，确认异常高亮和筛选有效。验证通过后移入对应 bughistory 模块并删除本文件。
