# GitHub 已更新但线上网页未同步

- **状态：** 未解决 / 待复现与定位
- **发现时间：** 2026-09-12T01:51:00+08:00
- **模块：** 发布与线上运行
- **关联模块：** 前端与交互

## 现象

按要求完成代码修改并产生 GitHub commit 后，线上网页仍可能继续展示旧行为，导致“仓库已经修复”和“用户实际看到的页面”不一致。

## 当前已知

目前只能确认存在“提交状态与线上页面状态不同步”的现象；尚未拿到足够证据判断具体根因。可能涉及的检查点包括：生产服务器是否拉到最新 main、服务是否完成重启、静态资源版本是否更新、浏览器/CDN 缓存是否仍命中旧资源等，但在验证前都不能写成根因。

## 后续定位要求

需要在同一次复现中完整记录：

1. `origin/main` 目标 commit SHA；
2. 生产服务器 `/opt/activity-timeline` 实际 HEAD；
3. `activity-timeline` systemd 当前启动时间与运行入口；
4. 页面实际返回的 HTML/JS/CSS 版本或关键新代码是否已经存在；
5. 强制刷新/无缓存请求后的浏览器行为；
6. 若有反向代理或 CDN，再核验其缓存状态。

## 解决验收

只有同时满足以下条件，才可以从 open bug 移入 `bughistory/deployment-release.md`：

- 已明确根因；
- 修复代码已提交；
- 生产环境实际运行目标 commit / 构建版本；
- 线上接口或浏览器页面实际验证新行为；
- 能区分“代码没部署”“服务没重启”“静态资源缓存”这几种不同失败模式。
